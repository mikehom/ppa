## Summary

Exception analysis subtracts handled exceptions from effects (rule [handle], Table 5.10). On an effect variable the book defines β\{s} = β, even though β might later be instantiated to {s} [PPA §5.4, p. 329] (book p. 329; PDF p. 346). Generalisation must not quantify variables free in the effect (illustrated by Example 5.36).

## Technical Analysis / Mechanism

Per the book, β\{s} = β is semantically sound, because β\{s} ⊆ β should hold for all instantiations of β (as in rule [sub]); "to define a less approximate system" it would be natural to add φ ::= ··· | φ\{s} and extend the UCAI axiomatisation to set difference [PPA §5.4, p. 330] (book p. 330; PDF p. 347). Erasing the subtraction on effect variables is therefore sound but less precise; keeping φ\{s} symbolically is the more precise option. [external] Dropping the generalisation side condition admits type confusion through polymorphic channels and references.

Guardrail: L2: enforce the generalisation side condition explicitly; accept β\{s} = β as the sound default, and where precision matters represent subtraction on effect variables symbolically (φ\{s}) with the extended axiomatisation.
