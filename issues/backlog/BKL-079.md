## Technical Analysis / Mechanism

Three subtle mechanisms affect Table 5.10 exception polymorphism [PPA Table 5.10, p. 328] (book p. 328; PDF p. 345): (1) simplifying symbolic set difference beta \ {s} to empty on an uninstantiated effect variable beta [PPA §5.4.2, p. 330] (book p. 330; PDF p. 347) erases any distinct exception s' != s later substituted for beta in (fn g => handle s as 0 in g 1), causing silent uncaught-exception [external: false negatives]; (2) pruning a handler branch in Exercise 5.14 [PPA Exercise 5.14, p. 362] (book p. 362; PDF p. 379) using only s notin phi_2 without checking AV(phi_2) = empty drops reachable handlers whenever phi_2 contains an effect variable that instantiates to {s}; and (3) Exercise 5.15 [PPA Exercise 5.15, p. 363] (book p. 363; PDF p. 380) prints monotype tau_hat <= tau_hat' where polymorphic schemes require sigma_hat <= sigma_hat', while Example 5.30 [PPA Example 5.30, p. 329] (book p. 329; PDF p. 346) uses '0 outside §5.3.2's '1-based AVar naming.

Guardrail: Preserve beta \ {s} = beta (or symbolic difference terms), enforce AV(phi_2) = empty before pruning handlers, close [gen] downwards through constraints, and define sigma_hat <= sigma_hat' on schemes. (Refs: F-U5b-04, F-U5b-13, G-U5b-08, G-U5b-09, G-U5b-10, G-U5b-11, G-U5b-12, G-U5b-26, BKL-009).
