## Summary

`architecture/ARCHITECTURE.md` §7.2 asks that every formal statement above `L3` keeps the bounds, direction, and quantifiers of the cited book statement. No checker implements this, so it works as a Tier B (review-only) rule. The post-reset-v1 audit found two defects of exactly this kind that had reached closure: `MFP = MOP` restated as a biconditional, and the `d(G_𝒮, T) + 3` Round Robin bound widened beyond Bit Vector Frameworks. Both were found by humans, not by a check.

## Source Citations & Grounding

- [PPA Lemma 2.32, p. 80] (book p. 80; PDF p. 99): "If the framework is distributive and if path∘(ℓ) ≠ ∅ for all ℓ in E and F then MFP = MOP". This is an implication, not a biconditional.
- [PPA Lemma 6.12, p. 380] (book p. 380; PDF p. 396): the bound holds "under the assumptions stated above", i.e. only for instances of a Bit Vector Framework.
- [PPA Exercise 6.14, p. 391] (book p. 391; PDF p. 407): defines fast functions and the fastness closure and states no Round Robin iteration bound.

## Technical Analysis / Mechanism

Signature distortion keeps every citation coordinate valid, so `inline_citations`, `concept_citations`, and `C1.8` multiset parity all pass. Two forms were observed:

1. **Quantifier/connective strengthening**: `if A and B then C` becomes `C iff A and B`. This adds a necessity claim the source does not make, and the added claim is false in general: a non-distributive framework on a merge-free program still has `MFP = MOP`. It was found in `ontology/concept_graph.json` (`ppa.dfa.mop-vs-mfp.formal_summary`) and `ontology/cross_paradigm_matrix.md`.
2. **Hypothesis widening**: a bound proved for one framework class is quoted for a larger class (Bit Vector → "fast distributive"). It was found in the `ppa-fixedpoint-solvers` skill, its `L0` ambient file, the graph `conditions` of `ppa.solvers.round-robin-loop-bound`, and `RAW_SHARD_06` gotcha `G-U6-13`.

Proposed minimal automation:

- for every `formal_summary`, `conditions` item, and `L1`/`L2` sentence carrying an N8 citation to a numbered Lemma/Proposition/Theorem/Corollary, extract connective and quantifier tokens (`iff`, `if … then`, `only`, `all`, `every`, `for all`, `∀`, `∃`, `never`, `strictly`, `⊑`/`⊏`, `⊒`/`⊐`);
- compare them with the token set of the cited `L3` anchor sentence in `corpus/shards/`;
- report a strengthening (`iff` above an `if … then`, `⊏` above `⊑`, a widened class name) as a `SIGNATURE_DISTORTION` finding.

Until that exists, §7.2 (`arch_7_2_signature_parity`) and the §7.1 L1-anchor clause (`arch_7_1_l1_anchor_parity`: 6 nodes currently have fewer L1-anchor list/table entries than graph `conditions`, and 59/79 referenced L2 sections do not directly link the node's L1 file, while discrete node `conditions` and compiled wiki card parity are enforced in Tier A) must be reported as `NOT_IMPLEMENTED` in every validator mode, never as passed.
