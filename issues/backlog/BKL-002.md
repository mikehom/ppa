## Summary

Upper bound operators (and hence widenings) are explicitly not required to be monotone, commutative, associative or absorptive.

## Technical Analysis / Mechanism

A widening operator is an upper bound operator [PPA §4.2, p. 226] (book p. 226; PDF p. 243), and upper bound operators are not required to be monotone [PPA §4.2, p. 225] (book p. 225; PDF p. 242). A summary that treats widening as monotone therefore states a property the book does not give: a larger input to ∇ need not give a larger result, and ∇ need not be commutative (the book's interval example on p. 225 gives different results for swapped arguments), so precision of the widened iteration can depend on the order in which values arrive. Exercise 6.13 asks for a worklist algorithm with widening and for proofs that it over-approximates the least solution and terminates even without the Ascending Chain Condition. Note that x ⊔ (x ∇ y) = x ∇ y, because x ∇ y ⊒ x for an upper bound operator; that wrapping is not a hazard.

Guardrail: L2: never claim that a widening operator is monotone, commutative, associative or absorptive; quote the termination argument for the widened iteration, not a monotonicity argument. [external] In chaotic-iteration solvers, apply widening only at cycle cut points (e.g. targets of back edges for a depth-first spanning forest) and follow with narrowing where precision matters.
