## Technical Analysis / Mechanism

Section 6.2.1 [PPA §6.2.1, p. 380] (book p. 380; PDF p. 396) contains two specification traps: (1) its comparison to Chapter 2's O(b^2) Reaching Definitions bound mis-cites Example 2.8 (Very Busy Expressions, [PPA Example 2.8, p. 46] (book p. 46; PDF p. 65)) instead of Example 2.30 [PPA Example 2.30, p. 78] (book p. 78; PDF p. 97); and (2) its Bit Vector Framework template over P(D) leaves lattice order <= in {subseteq, supseteq} implicit until Mini Project 6.1 [PPA Mini Project 6.1, p. 387] (book p. 387; PDF p. 403) and requires a flow variable x_{j_i} in every RHS (requiring Y_1^1 = empty on a dummy variable for constants), so assuming <= = subseteq breaks must-analyses (AE/VB) and applying Lemma 6.12 [PPA Lemma 6.12, p. 380] (book p. 380; PDF p. 396) to non-fast domains (Constant Propagation, Example 6.6 0-CFA [PPA Example 6.6, p. 373] (book p. 373; PDF p. 389) vs Example 6.5 [PPA Example 6.5, p. 373] (book p. 373; PDF p. 389)) understates pass counts.

Guardrail: Cite Example 2.30 for O(b^2), support both subseteq and supseteq Bit Vector lattices, and explicitly enforce Lemma 6.12 preconditions. (Refs: F-U6-06, F-U6-10, G-U6-13, G-U6-14, G-U6-15).
