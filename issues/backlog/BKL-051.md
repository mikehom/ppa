Page 142 uses semicolon multi-let sugar absent from the single-binding FUN grammar; pp. 146 and 155 have minor prose typos; Table 3.2 [app_fun] appends [x |-> v_2] rightmost after [f |-> close ...]; Table 3.3 [let_2] restricts to FV(e_2) without subtracting x.

## Technical Analysis / Mechanism

Formal FUN grammar (`t ::= let x = e1 in e2`) permits one binding per `let`, so semicolon chains on p. 142 require nested desugaring. In Table 3.2 `[app_fun]`, `rho2 = rho1[f |-> close (fun f x => e1) in rho1]` and `(bind rho2[x |-> v2] in e1)^l` places `[x |-> v2]` rightmost (matching Example 3.8 `[f |-> ...][x |-> ...]`). In Table 3.3 `[let_2]`, `rho0 = rho | FV(e2)` omits subtracting `x`, retaining shadowed outer `x` underneath `[x |-> v]`.

Guardrail: Desugar multi-binding let into nested AST nodes, keep [x |-> v_2] rightmost in [app_fun], and read [let_2] rho_0 = rho | FV(e_2) verbatim. (Refs: F-U3a-01..04, G-U3a-01, G-U3a-02, G-U3a-08, G-U3a-09, G-U3a-11).
