## Summary

Length-N bit-vector W.p scans N bits per refill (O(h*N^2) under sparse refills), and Figure 6.3 row 6 displays the refilled W.c one step earlier than Table 6.3 executes (unlike Figure 6.6).

## Technical Analysis / Mechanism

In Table 6.3 [PPA Table 6.3, p. 376] (book p. 376; PDF p. 392) and §6.2 [PPA §6.2, p. 378] (book p. 378; PDF p. 394), representing W.p as a dense length-N bit vector forces a full 1..N scan on every W.c = nil refill; on a sparse chain where each pass flips only O(1) bits across Theta(h * N) refills, scan overhead degrades to Theta(h * N^2) unless backed by a [external: sparse-set] or Exercise 6.7's two-queue routing [PPA Exercise 6.7, p. 390] (book p. 390; PDF p. 406). Independently, Figure 6.3 row 6 [PPA Figure 6.3, p. 377] (book p. 377; PDF p. 393) prints the refilled W.c one step before Table 6.3's extract() triggers the swap (whereas Figure 6.6 [PPA Figure 6.6, p. 384] (book p. 384; PDF p. 400) shows deferred refill), causing trace-oracle assertions to fail if both tables are tested against one convention.

Guardrail: Pair sparse RPO queues with [external: sparse-set] tracking or two-queue priority routing (Exercise 6.7) and document Figure 6.3's display convention. (Refs: F-U6-04, F-U6-05, G-U6-11, G-U6-12).
