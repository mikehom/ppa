## Summary

Mini Project 3.1 prose line 10 (p. 202) prints (C_hat, rho_hat, R_hat) |=_s t_0^{l_0} missing prime ' from |='_s; Mini Project 3.2 (p. 203) stores flat constructor labels C(l_1, ..., l_n) in Val_hat, breaking Fact 3.11 and Theorem 3.10 during SOS label rewriting.

## Technical Analysis / Mechanism

In `Mini Project 3.1` (p. 202), dropping the prime on `|='_s` in prose conflates reachability-gated evaluation with unconditional `Table 3.5`. In `Mini Project 3.2` (p. 203), `Val_hat = P(Term union {C(l_1, ..., l_n) | C in Constr, l_i in Lab})` embeds expression labels `l_i` inside abstract values (`case e_0 of C(x_1, ..., x_n) => e_1 or x => e_2`), which breaks `Fact 3.11` and `Theorem 3.10` when small-step SOS rewrites outer labels unless inner values drop labels or track canonical constructor sites.

Guardrail: Use |='_s throughout Mini Project 3.1 (p. 202) and isolate or strip expression labels from Val_hat constructor payloads in Mini Project 3.2 (p. 203). (Refs: F-U3b-08, F-U3b-09, G-U3b-25, G-U3b-26).
