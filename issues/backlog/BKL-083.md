## Summary

Table 6.5 initialises scc := 1, shadows scc in 'for each scc in topological order do', writes srPostorder[x >= t] := (scc, rp), and increments scc := scc + 1.

## Technical Analysis / Mechanism

Table 6.5 [PPA Table 6.5, p. 382] (book p. 382; PDF p. 398) initialises integer counter scc := 1, then rebinds the exact same identifier as the loop variable in 'for each scc in topological order do', computes local rPostorder on that component set, stores (scc, rp) into srPostorder[x >= t], and attempts scc := scc + 1. Under lexical scoping the inner set shadows the counter so every component receives a non-comparable set object or identical rank 1; under flat scoping the loop overwrites the integer with a set, raising a runtime type error on scc + 1 and breaking the lexicographic topological priority ordering required by Table 6.6.

Guardrail: Separate integer counter scc_id from component set comp in all derived pseudocode and implementations while preserving verbatim Table 6.5 at L3. (Refs: F-U6-08, G-U6-16).
