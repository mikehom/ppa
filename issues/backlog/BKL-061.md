## Technical Analysis / Mechanism

In `Mini Project 3.4` (`(new_pi x := e_1 in e_2)^l | (! x)^l | (x := e_0)^l | (e_1 ; e_2)^l`, pp. 204-205), multiple dynamic `new_pi` allocations share one summary token `pi in Pnt`, and `Table 3.1`-style `|=_{me}` must thread stores `S_circ`/`S_bullet` conservatively across all `Pnt` cells via weak updates (`[external: weak update]`). Performing destructive strong updates (`"kill"`, `[external: strong update]`) without **both** per-program-point local stores and singleton abstract reference counts (`p. 200` `[133]`) silently drops aliased heap pointees.

Guardrail: Formulate |=_{me} with weak-update ([external: weak update]) store joins preserving unaffected p' in Pnt, and gate strong updates ([external: strong update]) strictly on local stores + singleton reference counts (p. 200 [133]). (Refs: F-U3b-09, G-U3b-27, G-U3b-30).
