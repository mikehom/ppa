## Summary

Valid solutions of coupled |=_d (Table 3.8) and |=_D (Table 3.9) prune dead branches and therefore need not satisfy Table 3.1 |=; testing iota_true <= D_hat(l_0) in Table 3.9 is unsound if iota_true covers multiple concrete truthy values; Example 3.29 f_+ requires strict bottom checks before top.

## Technical Analysis / Mechanism

Dead-branch pruning in `|=_d` (Table 3.8) and `|=_D` (Table 3.9) suppresses unreachable `then`/`else` clauses, so coupled solutions need not satisfy plain Table 3.1 `|=`. Under Table 3.9, checking `iota_true <= D_hat(l_0)` silently skips the `then` branch whenever `iota_true` abstracts multiple concrete truthy values (e.g., `iota_true = top_Z` vs constant `1`). In Example 3.29, `f_+` must check bottom `bot` strictly before `top` to preserve error-free/dead-branch strictness.

Guardrail: Enforce Data finiteness / L ACC, test non-disjointness D_hat(l_0) meet iota_true != bottom when truthy values are non-singleton, and keep binary operators bottom-strict. (Refs: F-U3b-01, F-U3b-02, G-U3b-01, G-U3b-02, G-U3b-03, G-U3b-04, G-U3b-05, G-U3b-06, G-U3b-07, G-U3b-08, G-U3b-09).
