## Summary

BExp grammar includes true and false and §2.1 uses [true]^{ℓ'}, yet Table 2.5 omits ℬ⟦true⟧σ = true and ℬ⟦false⟧σ = false.

## Source Citations & Grounding

- [PPA Table 2.5, p. 55] (book p. 55; PDF p. 74)
- [PPA §1.2, p. 4] (book p. 4; PDF p. 24)
- Statements confirmed against rendered page images during Unit 2 extraction.

## Technical Analysis / Mechanism

Table 2.5 defines boolean valuation `ℬ⟦b⟧σ` across negation (`not`), conjunction (`and`/`or`), and relational comparisons `a₁ op_r a₂`, while omitting the base literal equations `ℬ⟦true⟧σ = true` and `ℬ⟦false⟧σ = false` despite `true`/`false` appearing in the `BExp` syntax (`Table 1.2` / `§2.1`) and in `[true]^{ℓ'}` loop examples (`§2.1.2`). Implementing `Table 2.5` literally causes constant boolean guards `[while true]` or `[if false]` to become undefined during concrete SOS simulation and dead-branch checks.

Guardrail: Include explicit boolean literal clauses ℬ⟦true⟧σ = true and ℬ⟦false⟧σ = false in expression evaluators. (Refs: F-U2a-06, G-U2a-15).
