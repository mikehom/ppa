## Summary

On p. 197, printed CPA [app] omits a closing parenthesis ")" before ^l and writes {delta_b} <= rho_hat(x_1) x ... x rho_hat(x_m) omitting ", delta_b"; p. 198 writes Delta = Term; any empty argument C_hat(l_j, delta) = empty collapses the Cartesian product to empty.

## Technical Analysis / Mechanism

In §3.6.2 `CPA`, `Env_hat = (Var x Delta) -> Val_hat` takes two arguments `(x_i, delta_b)` as shown in `[var]` (`rho_hat(x, delta)`), so p. 197's `{delta_b} <= rho_hat(x_1) x ... x rho_hat(x_m)` omits `, delta_b` and drops `)` before `^l` in `(t_0^{l_0}(t_1^{l_1}, ..., t_m^{l_m})^l` (the body `t_b^{l_b}` and `C_hat(l_b, delta_b) <= C_hat(l, delta)` are printed cleanly). Separately, if any argument `j` evaluates solely to a base constant with empty `C_hat(l_j, delta) = empty`, the Cartesian product becomes empty and skips the call body.

Guardrail: Bind {delta_b} <= rho_hat(x_1, delta_b) x ... x rho_hat(x_m, delta_b), read p. 198 Delta as union_{m>=1} Term^m, and populate base-type tokens in C_hat(l_j, delta) so non-function arguments do not empty the product. (Refs: F-U3b-05, F-U3b-06, G-U3b-17..20, BKL-007).
