## Technical Analysis / Mechanism

Table 6.1 Step 1 [PPA Table 6.1, p. 369] (book p. 369; PDF p. 385) places Analysis[x] := bot and infl[x] := empty inside 'for all x >= t in S do' (omitting ';' after insert, parallel to Table 6.4's missing ';' after Analysis[x] := bot [PPA Table 6.4, p. 379] (book p. 379; PDF p. 395)). Whenever a constraint system contains an unconstrained input variable y in FV(t) \ LHS(S) (violating §6.1's standing assumption FV(t_i) subseteq X [PPA §6.1, p. 367] (book p. 367; PDF p. 383)), Step 2's evaluation of t dereferences an uninitialised Analysis[y] slot and Step 1's dependency loop crashes or skips registering infl[y]; meanwhile multi-inequation LHS variables are redundantly overwritten on every clause.

Guardrail: Initialise Analysis[x] and infl[x] explicitly over X = LHS(S) U Union_i FV(t_i). (Refs: F-U6-01, G-U6-04).
