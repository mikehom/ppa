## Technical Analysis / Mechanism

In Table 5.11 [region] [PPA Table 5.11, p. 334] (book p. 334; PDF p. 351), writing {rn_vec} intersect dom(sigma) = empty instead of dom(sigma_1) allows fresh regions to collide with allocations made during intermediate evaluation if store state sigma_1 already allocated rn_i, corrupting stack-region pop (sigma_2 \\ rn_vec) into dangling pointers. In Table 5.12 [var] [PPA Table 5.12, p. 337] (book p. 337; PDF p. 354), omitting '@ r' on sigma_hat conflates boxed extended types with unboxed schemes, while Table 5.13 [sub] [PPA Table 5.13, p. 338] (book p. 338; PDF p. 355) invokes <= without defining Type_RI variance (making r_1/r_2 covariant instead of invariant allows reading/writing across deallocated regions). Finally, applying [region] without BOTH Observe [PPA §5.4.3, p. 339] (book p. 339; PDF p. 356) and rho_vec occurring in phi wraps escaped return regions or inserts dead empty regions.

Guardrail: Check {rn_vec} intersect dom(sigma_1) = empty, keep r_1, r_2 invariant in Type_RI arrow subtyping, preserve compound forall[]. tau_hat, and verify rho_vec in phi before letregion wrapping. (Refs: F-U5b-05, F-U5b-06, F-U5b-07, G-U5b-13, G-U5b-14, G-U5b-15, G-U5b-16, G-U5b-17).
