## Summary

Table C.1 and the dominator definition assume a handle H from which every node is reachable; Example C.6 states that final(S) is a handle of the backward flow graph `(labels(S), flowᴿ(S))` for WHILE statements (which holds unconditionally by structural syntax because `final(while [b]^ℓ do S₀) = {ℓ}`).

## Technical Analysis / Mechanism

In WHILE, `flow(S)` and `final(S)` are purely syntactic, so even semantically non-terminating loops (`while [true]^1 do [skip]^2`) remain syntactically reachable from `final(S)` in `flowᴿ(S)`. By contrast, in general compiler/binary CFGs `[external]`, dead blocks or undiscovered indirect-jump targets are unreachable from the entry (so DFS leaves them unnumbered and greatest-solution dominator equations give them `Dom(n) = N`), and syntactic exit-less sink loops (e.g. `for(;;)` with no `break`/`return` edge) leave loop nodes unreachable from exit blocks in the backward CFG, invalidating naive post-dominance claims (`[external]`).

Guardrail: L2: verify the handle covers every node (add a dummy root for multiple entries); track unreachable components explicitly instead of letting them inherit ⊤.
