# Cross-Paradigm Synthesis, Unification Catalog, and Paradigm Selection Protocol

Synthesises the five analysis and solver paradigms of *Principles of Program Analysis* across
Chapters 1–6 and Appendices A–C:

1. **Data Flow Analysis (DFA)** — Monotone Frameworks, equational/constraint flow systems, interprocedural call strings / assumption sets, and heap Shape Graphs (`Chapters 1–2`) [PPA §2.1, p. 35] (book p. 35; PDF p. 54).
2. **Control Flow & Constraint-Based Analysis (CFA)** — Coinductive and syntax-directed flow logics, conditional set constraints, `0-CFA`, mixed data/control flow, uniform `k`-CFA, and Cartesian Product polyvariance (`Chapter 3`) [PPA §3.1, p. 141] (book p. 141; PDF p. 159).
3. **Abstract Interpretation (AI)** — Correctness relations, Galois connections and insertions, widenings/narrowings, systematic lattice combinators, and induced optimal transformers (`Chapter 4`) [PPA §4.1, p. 211] (book p. 211; PDF p. 228).
4. **Annotated Type and Effect Systems** — Underlying `FUN` types, UCAI-quotiented control-flow annotations, polymorphic type/effect reconstruction, subtyping/subeffecting, region inference, and concurrent behaviours (`Chapter 5`) [PPA §5.1, p. 283] (book p. 283; PDF p. 300).
5. **Fixed-Point Algorithms & Solvers** — Abstract worklist engines, LIFO/FIFO, reverse postorder, Bit Vector Round Robin, strong-component (SCC) scheduling, and demand-driven / elimination backends (`Chapter 6`) [PPA §6.1, p. 365] (book p. 365; PDF p. 381).

## Canonical Concordance Note (`U1`–`U10` and `X1`–`X5`)

Unification identifiers `U1`–`U10` follow the canonical architecture graph schema (matching `concept_graph.json` edges): equational vs constraint DFA (`U1`), Monotone Framework `MFP` vs Chapter 6 worklist (`U2`), `0-CFA` graph solver vs Chapter 6 worklist (`U3`), Monotone Frameworks vs `CFA + DFA` (`U4`), call strings / assumption sets vs `k`-CFA / `CPA` (`U5`), Galois induced operations vs DFA/Chapter 1 transfers (`U6`), widening `∇` vs ACC (`U7`), annotated types vs constraint CFA (`U8`), Tarski fixed points vs induction/coinduction & CFA (`U9`), and Appendix C graph theory vs RPO/SCC iteration (`U10`). Additional structural cross-chapter bridges—Shape vs Regions (`X1`), Distributive `MFP = MOP` vs `α`-additivity (`X2`), `∇` worklists & `WTO` `[external]` cutsets (`X3`), Coinduction vs `0-CFA` & Concurrent Behaviours (`X4`), and Chapter 1's five formulations vs Appendix A Tarski / ascending-chain (`Kleene` `[external]`) (`X5`)—are indexed as `X1`–`X5` alongside canonical `U1`–`U10` so no machine identifier collides.

### 3.2 Domain-Specific Triage Workflows

#### Software Engineering & Compiler Optimization
1. Check whether target IR has dynamic dispatch or closures: if **statically dispatched**, stay in Chapter 2 Bit Vector / Monotone Frameworks with Chapter 6 `Table 6.6` SCC + RPO (`d(G_𝒮, T) + 3` Round Robin when Bit Vector, `O(h · M · N)` split RHSs via `Exercise 6.5` otherwise).
2. If **typed higher-order** with acceptable monomorphic merging, run `𝒲_CFA` (`Table 5.8`, `PTIME` `[external]` structural unification) before reaching for `0-CFA` (`O(n³)`) or exponential `k`-CFA (`§3.6.1`).
3. If optimising **higher-order branches** (`[180]`, `[external: SCCP]`), compose **`§3.5` (`CFA + DFA`)** with lazy conditional expansion (`[9]`, `[external: Aiken & Wimmers 1993]`, `Ch 3 CR`) rather than eager cross-product instantiation.
4. Before converting `0-CFA` to `1-CFA` (`§3.6.1`), always **α-rename bound variables apart** (`p. 199`) [PPA Chapter 3 Concluding Remarks, p. 199] (book p. 199; PDF p. 217); if hubs (`map`, event dispatch) still saturate, test `1-CFA` or `CPA` (`§3.6.2`)—empirical runtime frequently *drops* despite exponential worst-case (`[80]`, `[external: Jagannathan & Wright 1995]`).

#### Cybersecurity & Vulnerability Analysis `[external]`
1. **Uninitialised variable / tainted-source slicing `[external]` (`§2.1.5`)**: Verify `? ∈ Lab⋆^?` is tracked (`RD` `ι = {(x, ?) | x ∈ FV(S⋆)}`) so `UD(x, ℓ')` surfaces every read-before-write or unvalidated input sink (`Example 2.12`) [PPA Example 2.12, p. 54] (book p. 54; PDF p. 73).
2. **Dead-store elimination vs cryptographic secret zeroization `[external]`**: Closed-world `LV_exit(final) = ∅` silently deletes trailing `[key := 0]^ℓ` wipes; seed `observed_outputs` and sensitive buffer clears in `ι` at `final(S⋆)` (`§2.1.4`).
3. **Indirect-call / Control-Flow Integrity (`CFI`) `[external]` target tightening (`§3.5`, `§3.6`)**: Pair `1-CFA` / `CPA` with `§3.5.1` guard filtering so callback/`vtable` `[external]` sinks do not collapse across unrelated callers, while guarding closure contour depth (`ce | FV(t)` and polynomial `𝒫(Term × Δ)`) to prevent analyzer `CWE-400` `[external]` DoS [PPA §3.6.1, p. 195] (book p. 195; PDF p. 213).
4. **Memory safety / Use-After-Free & null dereferences `[external]` (`§2.6`)**: Enforce all three `kill_{x.sel}` unsharing guards (`n_U ∈ is`, `#into ≤ 1`, **and** `¬∃sel' : (n_∅, sel', n_U) ∈ H'`) before clearing heap-sharing bits (`§2.6.3`) [PPA §2.6.3, p. 125] (book p. 125; PDF p. 144), and report null dereferences directly from `Case 1` pre-states (`Shape∘(ℓ)`).
5. **Information flow / timing & termination lockstep (`§2.2.2`, `§5.5`)**: Low-equivalence lockstep bisimulation (`σ₁ ∼_{N(ℓ)} σ₂`, `Theorem 2.21`) enforces `non-interference` `[external]` when branch guards stay low (`N(ℓ) ⊇ FV(b)`); for concurrent systems, keep `τ̂ chan r` **invariant** (`Table 5.18`) and block type-variable generalisation across free channel effects (`Example 5.36`).

#### Program Verification & Formal Correctness Auditing
1. **Infinite-state proofs (`§4.2`–`§4.5`)**: Derive transfer functions via `(α, γ)` (`§4.5.1`), verify `γ(ȷ) = ι` (`(4.11)–(4.12)`), enforce reduced products (`ς[M₁ × M₂]`, `§4.4.2`), place `∇` strictly on SCC loop-head cutsets (`[25]` `[external]`, `Exercise 6.13`), and apply a bounded `Δ` narrowing pass (`§4.2.2`).
2. **Proof-style selection (`Appendix B`)**: Choose **small-step SOS** (`§2.2`, `§3.2`, `§5.5`) whenever invariants must hold across non-terminating loops or reactive servers; never rely solely on environment-free big-step Natural Semantics (`Theorem 5.9`) to assert non-vacuous safety on diverging executions.
3. **Worklist & solver sanity (`Ch 6`)**: Always guard updates with `Analysis[x] ⋣ new` (never `≠`) and join via `⊔` (never overwrite); verify bit-vector assumptions before claiming `O((d + 1) · N)` (`Lemma 6.12`) bounds; verify monotonicity of any assumption-set context (`§2.5.5` `Δ = 𝒫(D)` equality fails monotonicity unless relaxed to `⊆`).

### 3.3 Escalation Anti-Patterns (When NOT to Upgrade)

- **Do NOT deploy `§2.5.5` Large Assumption Sets (`Δ = 𝒫(D)`) with exact equality**: Exact `δ' = {d'' | (δ, d'') ∈ Z}` breaks monotonicity (`Example 2.41`) [PPA Example 2.41, p. 99] (book p. 99; PDF p. 118); use `Small Assumption Sets` (`Δ = D`, additive `IFDS`-style `[external]`) or relax to `⊆`.
- **Do NOT upgrade `0-CFA` to uniform `1-CFA` without `ce | FV(t)` or flat contours**: Unbounded closure environments jump directly to `DEXPTIME` `[external]` worst-case blowup (`§3.6.1`).
- **Do NOT compose individually optimal Galois transformers expecting an optimal pipeline**: `g₂ ∘ g₁` only over-approximates `(α₃ ∘ (f₂ ∘ f₁) ∘ γ₁)` (`Exercise 4.20`).
- **Do NOT assume SCC/RPO order-invariance remains true once `∇` (`Exercise 6.13`) is enabled**: Widening turns solver iteration schedule from a pure performance tuning knob into a semantic precision parameter.
